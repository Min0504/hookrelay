# k6 부하 결과

로컬 Docker Desktop, Apple Silicon, compose 스택 1워커. 2026-08-14.

```bash
docker compose up --build -d
./bench/seed.sh
./bench/run.sh
```

원본: `bench/out/*-summary.json`.

## ① 발행 80 RPS × 20s

API만 때린다. 배달 HTTP와 분리되어 있으므로 워커 적체와 무관해야 한다.

| 지표 | 값 |
|---|---|
| 도착률 | 80 RPS |
| 반복 | 1,600 |
| 202 비율 | **100%** |
| API p50 | 6.8 ms |
| API p95 | **14.4 ms** |
| API p99 (max) | 202 ms |

nginx `limit_req` 뒤로 붙이면 80 RPS에서 503이 난다. 부하 측정은 API 포트(:3000)로 직접 보낸다. 500 RPS는 `RPS=500 DURATION=30s ./bench/run.sh`.

## ② noisy neighbor

테넌트 A = `/hooks/slow`(800ms), 테넌트 B = `/hooks`. 측정은 발행→SUCCEEDED 폴링.

| 조건 | A 배달 p95 | B 배달 p95 | 비고 |
|---|---|---|---|
| 격리 ON (`HR_TENANT_CONCURRENCY=3`) | 8.7 s | 227 ms | 직전 1,600건 발행 적체가 남은 상태에서 측정 |
| 격리 OFF (`=0`) | 3.9 s | 10 ms | 큐가 가라앉은 뒤 |

이 부하(워커 동시성 10, slow 800ms, 15 RPS)에서는 B 잡이 짧아 슬롯 사이에 끼어든다. **세마포어의 본래 가치는 A가 10초 타임아웃으로 슬롯을 붙잡을 때**이며, 그 경로는 E2E(`isolation.e2e-spec.ts`)와 서킷 OPEN이 증명한다. 코드 기준점: 태그 `v0-no-isolation`.

같은 바이너리로 OFF 재현:

```bash
HR_TENANT_CONCURRENCY=0 docker compose up -d --no-deps --force-recreate worker
k6 run -e BASE=$BASE -e KEY_A=$KEY_A -e KEY_B=$KEY_B bench/k6/noisy-neighbor.js
```

## ③ DLQ 재배달

DEAD가 없는 깨끗한 시드에서는 재배달 카운터가 0이다. `/hooks/fail` endpoint로 실패를 쌓은 뒤 같은 스크립트를 돌린다. 재배달 API 자체 p95는 이번 런에서 **20 ms**.

## Redis 카오스

`DOWN_SEC=30 ./docs/chaos/redis-kill.sh`

- Redis stop 중 `POST /events` → **202**, deliveries 행이 DB에 생성됨
- Redis start 후 relay/worker 재기동(컨테이너 stop은 DNS가 바뀌어 ioredis가 `ENOTFOUND`) → 해당 이벤트 **SUCCEEDED**
